# Чистка после этапов A/B — чек-лист

*Ревизия всего кода 2026-09-06. Проходим поэтапно, каждая группа — отдельный коммит.
Порядок: сначала A (надёжность), потом B (упрощения), потом C (имена/комментарии).*

## A. Надёжность

- [x] **A1. Воркер TG_MTPROTO может умереть молча при старте.**
  `tg_client.session()` при первичном `ensure()` ловит только `NotAuthorized`;
  любая другая ошибка подключения (Telegram/DNS недоступны при старте контейнера)
  убивает задачу воркера, которую никто не await'ит — симптом только «очередь заполнена».
  Фикс: (а) в `session()` ловить при старте `Exception` (ensure() и так переподключается
  на каждой отправке — самолечение уже есть); (б) в `mqtt_dispatcher.main()` gather'ить
  воркеров доставки и cleanup вместе с `run_dispatcher()` — смерть задачи должна
  ронять процесс с traceback'ом.
- [x] **A2. Уведомление в пустоту.** `dispatch_notification` при пустом `_delivery_queues`
  (воркеры не запущены) молча ничего не делает. Guard: `logger.error(...)` + return.
- [x] **A3. `await summary_task` без защиты.** Неожиданное исключение в фоновой задаче
  сводки (например, KeyError на странном конфиге) уронит событие после того, как видео
  уже закодировано. Обернуть в try → `review_metadata = None` + `logger.exception`.

- [x] **B3. `_mtproto_send_media_group`:** второй `ensure()` (client уже есть у вызывающего —

- [x] **B5. `os.makedirs(CLIP_DIR)` при импорте** — побочный эффект и избыточно
  (`makedirs(review_dir)` создаёт родителей). Перенести в начало `cleanup_worker`
